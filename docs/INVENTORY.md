# INVENTORY — the corrected component inventory of ScreenExtend

Synthesized from the seventeen discovery reports in `docs/discovery/` (A–O, E1/E2, M1/M2, ~11,970
lines), with spot-checks against the working tree at `bef5f89`. Where a report and `CLAUDE.md`
disagree, the code wins and the disagreement is recorded at the end.

> **This is a snapshot of the tree at `bef5f89`, not a live document.** Much of what it records as
> a problem has since been fixed — CI exists, the log bus is off-thread, the per-adapter runtimes
> are one shared runtime, the audio bridge thread is gone, telemetry and a clock offset exist, and
> the macOS audio driver has run end to end. Read a row as "what was true when the audit ran", and
> check the code before acting on it. `docs/OPTIMIZATIONS.md` is the live record of what changed.

**230 components, `C-001` to `C-230`.** The prior pass listed ~99; this pass confirms most of
them, corrects 25, and adds the rest — chiefly the things that are structurally load-bearing but
were invisible from a feature-shaped reading of the product: the log-bus IPC emission, the two
1 Hz OS pollers, the per-adapter tokio runtimes, the audio bridge thread, the monaco preload, the
`os_workgroup`, the AirPlay mirror data port, the volume-key event tap, the CONSTQP rate-control
path, the vendored fork's dead Media Foundation encoder, the legacy-webkit checker, and the
clock-offset/telemetry gap that makes every latency claim in the product unmeasurable today.

## How to read the tables

**Path** — where the component sits:
`G2G` glass-to-glass video · `IN` remote input · `AU` audio · `JOIN` join/negotiation only ·
`START` startup only · `BG` background/steady-state load · `CTRL` control plane.

**Platform** — `W` Windows · `M` macOS · `L` Linux (scaffold) · `C` client browser · `X` all.

**Tier** — the capability tier the component belongs to, where the subsystem is tiered
(see `docs/CAPABILITY-TIERS.md`). `—` means the subsystem has no tier ladder.

**Status** — verification on the two dev boxes (Windows 11 build 26200 + RTX 3080 Ti Laptop,
hybrid graphics; macOS 10.15.8 Catalina Intel, Command Line Tools only):
- `VERIFIED` — runnable on a dev box here.
- `COMPILE-CHECKED` — builds and/or passes a static/layout test, never executed here.
- `UNVERIFIED` — no local signal at all (modern-macOS tiers, AMD, Linux, AirPlay in production).

**Known problems** cites `findings/*.md` by filename. `findings/` is the engagement's working
queue: it is excluded from git, a file is deleted the moment its finding is resolved, and the
whole directory goes away when the engagement ends. So **the prose in the cell is authoritative;
the filename is a pointer, and most of those pointers no longer resolve.** The fix for a
resolved finding is recorded in `docs/OPTIMIZATIONS.md`, not here. (At the time of writing all
269 distinct references resolved; the directory was also being consolidated concurrently, so some
were already stale then.)

Nothing in this inventory has been **measured**. `docs/BASELINE.md` is empty by design: no
before-numbers exist yet, and the history contains none either (report O §7.1 — ten commits are
explicitly about latency and not one cites a before/after figure).

## The join path, end to end

Not a component, but the thing every component above is measured against. Fully serial; nothing
overlaps (report A §11, report B §11, report K §11):

1. Client: `initSpeakers` + `needsMicPermission`, then the **microphone modal and `getUserMedia` — 0 to 12 s** (C-130).
2. Client: `prepare()` (AudioContext + `addModule`), `fetch('/ice-config')`, `new RTCPeerConnection`, `createOffer`, fetch + blob the transform worker (C-094).
3. Client: **`waitForIceGathering` — 0 to 3000 ms LAN, 6000 ms with TURN** (C-074; Google STUN is always in the list).
4. Host: `POST /whep` -> capacity, ban, approval, global pause, lockout, OTP, token mint (C-146 to C-148) — several mutex round trips on C-154.
5. Host: `spawn_blocking(stop).await` — a full encoder + capture teardown on any rejoin (C-150).
6. Host: **acquire `DISPLAY_CORRELATION_LOCK`** (process-wide) -> create the display -> correlate by name or **poll up to 5 s** (C-023), on macOS plus up to **3 s of `activate_mode`, twice for a Retina client** (C-012).
7. Host: `set_display_mode` -> `wait_for_display_settle` (always >= 75 ms) -> `apply_display_scale`.
8. Host: **`pipeline::start_on_monitor` on the async thread** — D3D11 device, encoder session, capture start, with a full DXGI fallback behind it ().
9. Host: negotiate, spawn five tasks and the injector thread, `set_remote_description`, `request_idr` (**discarded**, C-072), `create_answer`, **wait for gathering up to 1500 ms**.
10. Client: apply the answer, ICE, DTLS, SRTP; the track binds; the first frames are P-frames referencing a keyframe the client never saw, so the **client's own PLI is what actually starts the stream**.
11. Then `refineRefreshRate()` may tear the whole thing down and repeat it — on every 90/120 Hz phone (`major-client-refresh-rate-renegotiates-right-after-live`).

Worst case before DTLS begins: about 3 s + 5 s + 1.5 s plus the pipeline. And **every settings
change repeats all of it** (C-022).

## Corrections to the prior inventory

The prior ~99-item list was structurally right. These 25 entries were wrong, incomplete, or
named a thing that does not exist.

1. **"encoder selection + DXGI vendor detection"** — `select_vendor` does **not** drive backend
   selection. `build_backend` (`pipeline.rs:1346`) is a pure try-in-order ladder, and
   `select_vendor`/`device_vendor` are reachable only from the Intel same-adapter guard. The real
   adapter risk is *which adapter the capture D3D device lands on* (`D3D11CreateDevice(None, HARDWARE, …)`),
   not vendor misclassification. (C-060)
2. **"zero-copy NVENC texture ring"** — it is not zero-copy. There is always one full-frame
   GPU-to-GPU copy plus a forced `Flush()` on the capture callback thread, and one CPU
   allocation + memcpy out of the bitstream. "Zero-copy" here means zero *CPU* copies of the
   input surface only. (C-048)
3. **"Metal texture cache / IOSurface to CVPixelBuffer bridge"** — **there is no Metal texture
   cache and no Metal device.** `gpu.rs` is a 15-line empty stub with both fields commented out.
   Only the IOSurface-to-CVPixelBuffer wrap exists. (C-066)
4. **"frame repeater for static desktops"** — there are **two** different mechanisms with
   different behaviour: `spawn_repeater` (classic WGC and DXGI paths) and `ring_encode_thread`'s
   200 ms `recv_timeout` keepalive (NVENC ring). Only the first can emit an IDR. (C-036, C-037)
5. **"display-lag measurement from RTP timestamps"** — the client computes a number offset by an
   unknown constant (the host epoch is a process-local `Instant`). It is correct for A/V sync and
   is **not a lag**. (C-091, C-189)
6. **"mix-format negotiation / resample / BS.775 downmix" (Windows)** — the downmix and integer
   sample paths are **unreachable at runtime**, because `AUTOCONVERTPCM` guarantees 48 kHz/2 ch/f32
   before `convert_to_stereo_f32` is ever called. There is also no resampler in userspace. (C-099)
7. **"device trust tokens"** — correct, but `ScreenExtend serve` replays neither bans nor
   approvals, so a headless host silently un-bans every banned device. (C-148)
8. **"reconfig + kick epochs"** described as avoiding teardown — true of the *display* only. The
   client's `applyReconfig` does a full teardown and renegotiation of the WebRTC session, encoder,
   capture and injector thread. (C-022)
9. **"audio backend probing (5 tiers)"** — the count is right and the ladder is real, but the
   `VirtualDevice` tier is **unreachable in any shipped build** (the `.pkg` is never bundled) and
   is excluded on 13.0+ by a pure version window, so a modern Mac whose SCK start fails has no
   fallback. Effective support today: 14.2+ works, 13.0-14.1 works with a screen-recording
   indicator, 10.15-12.x has nothing. (C-105, C-114)
10. **"planar/interleaved normalization"** — present and correct, but `AudioFormatDesc::is_fast_path()`
    is **never consulted on macOS**, so the common case takes the slow byte-wise path. The Windows
    sibling does branch on it. (C-103)
11. **"Windows hosted network via netsh"** — there are **two mutually exclusive backends**
    (legacy `netsh` and WinRT WiFiDirect + Tethering), chosen by parsing localized `netsh` output.
    (C-161)
12. **"macOS hosted network via CoreWLAN / hostap.m"** — `hostap.m` is **compiled by nothing**;
    it is a checked-in gist with debugging `printf`s and hardcoded credentials. The live path is
    a private CoreWLAN SPI sent with no `respondsToSelector:` guard, in **HostAP mode, not
    ad-hoc**. (C-162, C-163)
13. **"macOS AirPlay-receiver fallback display tier"** — it only runs below 10.14.4, which is
    below the app's own `minimumSystemVersion` of 10.15, so **the shipped binary refuses to launch
    on every OS where this tier would be selected**. Nothing in the module says so. (C-014)
14. **"process/thread priority tuning"** — `streamer::input::tune_process()` has no callers, so
    `timeBeginPeriod(1)` and `HIGH_PRIORITY_CLASS` from the input module never execute. The
    streamer's `tuning.rs` does apply its own equivalents. (C-143)
15. **"24-opcode wire protocol"** — it is **25 opcodes**, including `BYE (0x63)` added in
    `ab37665` and `STATS (0x62)`, which is declared on both sides and never produced or parsed.
    (C-132)
16. **"canvas/video swap + render watchdog"** — there are **two** watchdogs (a 5 s first-frame
    timer and the 0.5 Hz render-stall check) and **four** independent triggers into a one-way
    `usingFallback` latch. (C-089)
17. **"auto-updater + latest.json patching"** — the comparator is custom and treats **any**
    version difference as an update, including a downgrade. (C-216)
18. **"tauri-specta binding generation"** — the export is double-guarded (debug **and** no CLI
    args) and writes to a **relative** path; running it against a stale binary silently reverts
    the API surface. (C-217)
19. **"legacy WebKit polyfill layer + build-time checker"** — the checker is a separate component
    with four structural blind spots and is the only automated compatibility gate in the repo;
    five post-13.1 CSS features ship today and it exits 0. (C-212)
20. **"IDR request path"** — `Pipeline::request_idr` is **invisible to the NVENC ring encode
    thread** (`wake_rx` dropped, `Encoder::request_idr` has no callers, `idr_requested` is
    permanently false), so a static desktop on the primary NVIDIA path can never produce a
    keyframe. (C-037, C-079)
21. **"loss-based bitrate controller"** — the controller itself is fine and well tested; the two
    things that break it are outside it: the **RTT unit mismatch** (seconds vs milliseconds) and
    **CONSTQP**, which makes `set_bitrate` a silently-logged no-op on all four encoder backends
    for every device that has a `videoQuality` override. (C-047, C-077)
22. **"GPU scaler + texture readback"** — the `Scaler` hardcodes BGRA for its destination,
    staging and views. There is **no NV12 output**, which is the single change that would serve
    the x264 CSC, the CPU-bridge readback size and a future AMF backend at once. (C-034)
23. **The client page has ten files, not nine** — `at-capacity.html` was missing from the list and
    is served by `server.rs::at_capacity_page`. (C-024, C-151)
24. **"single-instance lockfile + loopback control server"** — `serve` takes the lock and
    **never starts the control server**, so `ScreenExtend stop` cannot stop a headless host,
    which matters if `serve` is used for measurement runs. (C-167, C-219)
25. **"codec profile negotiation check" (client)** — the client parses the host's
    `profile-level-id` out of the answer, but **the host never reads the client's**. The profile
    is a config constant (default Baseline) and negotiation is one-directional. (C-073, C-092)

Additionally, three things the prior list treated as single items are split here because they
have different owners, threads and failure modes: display creation vs. display *reconfiguration*
(C-011 / C-012), the two idle keepalives (C-036 / C-037), and the volume proxy vs. the
`CGEventTap` backstop (C-112 / C-113).

   `tauri.macos.conf.json:5`); `git log` shows `4b745d1 build(release): bump version to 0.6.3`.
   Only the doc is stale, by three releases. (Reported independently by A, D, E1, E2, F, G, I, K,
   L, M1, M2, N.)
2. **The four "recovered" design notes.** `CLAUDE.md:637` says `AUDIO_NOTES.md`,
   `AUDIO_NOTES_MACOS.md`, `AUDIO_NOTES_MACOS_LEGACY.md` and `PRD-macos-legacy-audio.md`
   *"survive only in history, on the `sys-audio-winmac` branch (commit `420004a`)"*. **Three of
   the four never existed.** `git ls-tree -r --name-only 420004a` lists exactly six markdown files
   and none of them is an `AUDIO_NOTES_MACOS*`; scanning every tree of every reachable *and*
   dangling commit finds no file at any path by those names. Only `AUDIO_NOTES.md`, `PRD.md` and
   `DEVLOG.md` were ever committed and later deleted — all three are now in `docs/recovered/`.
   The macOS names appear only inside `//!` headers on dangling blobs, which is why the tree still
   cites documents that were never written. (O §2)
3. **Linux compiles.** *"`linux_utils/` Linux scaffold (compiles, mostly `bail!`s)"* — **it does
   not compile.** `streamer/pipeline.rs` has exactly two `cfg` blocks (windows, macos) and no
   `not(any(...))` arm, while `lib.rs:18` declares `mod streamer;` unconditionally and `server.rs`
   uses `pipeline::*` at eleven sites. `linux_utils/networking.rs` is **one blank line**.
   (`major-build-linux-does-not-compile`, `major-build-streamer-core-cannot-compile-on-linux`)
4. **The DPR ladder's transposes.** *"`dpr_mode_ladder` pre-registers one display mode per ratio
   … (plus each transpose, so an orientation flip is already registered)"* — `dpr_mode_ladder`
   (`server.rs:1196`) maps the ladder, sorts and dedupes. **It adds no transposed modes.** The
   Windows IDD backend adds them separately in `virtual_display.rs:87-101`; **macOS never
   overrides `create_display_with_modes` at all**, so `extra_modes` is discarded
   (`session.rs:637`, `let _ = extra_modes;`) and the whole ladder doctrine does not describe
   macOS.
5. **`gpu.rs` provides Metal.** *"`gpu.rs` — Metal device + `CVMetalTextureCache`"* — it is a
   15-line stub, `pub struct Gpu { _private: () }`, with both fields commented out. Consequently
   `CaptureError::NoMetalDevice` and `::TextureCache` are unconstructible. (C-066)
6. **macOS hosted network is ad-hoc.** *"`hosted_network.rs` + `hostap.m` — CoreWLAN **ad-hoc**
   network"* — the code calls `startHostAPModeWithSSID:`, i.e. **HostAP/infrastructure mode**.
   Nothing in the tree calls `startIBSSModeWithSSID:`. And `hostap.m` is compiled by nothing
   (`build.rs` is two lines of `tauri_build::build()`; there is no `cc` step). (C-162, C-163)
7. **Settings changes do not tear down.** *"Settings changes apply live via **epoch bumps** rather
   than tearing down the display"* — true of the display, false of everything else: the client's
   `applyReconfig` → `reconfigure()` → `teardownSession(); start(true)` rebuilds the entire WebRTC
   session, encoder, capture pipeline and injector thread, and retakes the process-wide
   `DISPLAY_CORRELATION_LOCK`. (C-022)
8. **The Windows audio conversion sentence.** *"48 kHz float32 stereo is the zero-copy fast path,
   everything else is `AUTOCONVERTPCM`'d / downmixed (ITU BS.775) / int→float"* — the three are
   not alternatives. `AUTOCONVERTPCM` is applied *first* and guarantees 48 kHz/2 ch/f32, which
   makes the downmix and integer paths **unreachable**; and the fast path is **not zero-copy** —
   it is about 960 load/clamp/push iterations per wake (`format.rs:137-139`). (C-099)
9. **CI is "temporarily disabled".** It **never ran**. `c3825d5` added `ci.yml` at 17:49:35 on
   2026-08-22 and `e1d5d28` deleted all 92 lines at 17:53:48 — 4 min 13 s later, with no edit in
   between and no reason in the message. The file is absent from `app-v0.4.0`, `app-v0.5.0` and
   `app-v0.6.3`. Restoring it is new work whose first run will be red, not a revert. (C-229)
10. **The legacy-WebKit checker's scope.** *"`node scripts/check-legacy-webkit.mjs` re-derives the
    list from `dist/` after a build and fails on anything unpatched"* — it reads `dist/assets/*.js`
    only: never CSS, never `dist/index.html`, never subdirectories, and it cannot fail a check
    carrying a `cover` annotation. Five post-13.1 CSS features ship today and it exits 0. (C-212)
11. **`transform-worker.js` "reports the display lag".** It reports a paint delay measured against
    a foreign epoch. There is no host/client clock sync anywhere in the product. (C-189, C-188)
12. **The audio ring ABI is a two-file contract.** *"its byte layout is a hard contract with
    `audio-worker.js` — change the two together"* — it is a **three-file** contract, because
    `audio.js` owns the allocation size (`makeSharedRing`). (C-127)
13. **`docs/airplay-fallback-design.md` is cited as an in-tree document** (`CLAUDE.md:373`, and
    from `airplay/receiver.rs:301`). The file is on disk but **untracked** — `.gitignore:44`
    ignores all of `docs/` — and its only committed revision lives in a dangling commit that
    `git gc` will delete. `CLAUDE.md` correctly flags the *other* four documents as missing and
    misses this one, which is the only one that is actually at risk. (C-230)

### Incomplete or out of date

14. **The registered-command list omits two commands** that are registered in `lib.rs` and used
    by the frontend: `set_window_zoom` (`lib.rs:347`, used by `zoom.ts:33`) and
    `get_display_capacity` (`lib.rs:374`, used by `dashboard.tsx:121` and gating the whole
    dashboard render).
15. **The macOS module list omits `macos_utils/objc_exception.rs`**, which `lib.rs:332` calls on
    every macOS launch, before the Tauri builder. (C-182)
16. **The macOS audio driver's path is wrong.** `CLAUDE.md` places it at `macos/ScreenExtendAudio/`;
    it is at **`src-tauri/macos/ScreenExtendAudio/`**.
17. **The repo map omits `linux-vdd/` (present, gitignored) and `scripts/`**, and the
    `windows_utils/` description omits `permissions.rs` and `device_reporter.rs`, both of which
    are part of the required per-OS surface.
18. **`pnpm approve-builds`** is still documented as the interactive step for a new dependency's
    build script; `0f745d8` removed it from CI and the setup docs in favour of `allowBuilds` in
    `pnpm-workspace.yaml`. Half-updated.
19. **The `streamer/static/` file list omits `at-capacity.html`**, the tenth file, served by
    `server.rs::at_capacity_page`.
20. **`README.md` still describes the old always-on CI** (`README.md:127` cites
    `.github/workflows/ci.yml`), and both `PROVENANCE.md` files say checksums are *"verified in
    CI"* by a job that was in the deleted file. `CLAUDE.md` notes the README paragraph is stale
    but not the provenance files.
21. **The Windows tier story is incomplete.** `CLAUDE.md` says the chosen tier is reported to the
    UI through `CompatibilityReport`. On Windows `audio_backend: "wasapi"` and
    `display_backend: "IddDriver"` are **string literals, not probes**, and there is **no field
    at all** for the capture backend (WGC vs DXGI) or the encoder backend (NVENC / Quick Sync /
    Quick Sync CPU bridge / x264) on either OS — the two choices with the largest latency
    consequence. (C-180)
22. **The vendored fork is described as "leave it as-is"**, which reads as frozen. `5ba1183`
    already modified it (frame-pool count 1 → 3), the matching `Recreate` still passes 1, and
    three of the highest-value capture fixes are one-file patches inside it. No version or
    upstream commit is recorded anywhere — it is `windows-capture` **2.0.0**, recoverable only
    from `git show ad598b2^:src-tauri/Cargo.lock`. (C-028, C-043)
23. **`amd.md` is cited without caveat.** It is a genuinely good spec, and it references a
    project "§16 photographic method", an "M-gating" scheme, a vendored `AMF/` directory and
    AI-tooling guidance — none of which exist in the tree or in `CLAUDE.md` any more. (C-059)
24. **The Safari 13.1 floor is stated as an achieved constraint.** The shipped stylesheet already
    contains `:focus-visible` (7 rules), `:where()` (4), `:has()` (1), `aspect-ratio` (1) and
    `inset-inline-start` (1), all silently dropped on the floor — and combined with
    `index.css:97`'s transparent outline, **the app has no visible keyboard focus indicator at all
    on macOS 10.15**. The client page has the same class of gap: `inset: 0` on six full-bleed
    layers (Safari 14.1). (C-212, C-095)
25. **`serve` is described as a complete headless host.** It starts no single-instance control
    server (so `ScreenExtend stop` cannot reach it, and its own error message says otherwise),
    drops device bans and approvals, reads a `disconnectGraceSecs` key the GUI never writes,
    never prints an HTTPS URL, and takes the OTP on argv. (C-219)
26. **The `AudioHub` description omits the bridge thread.** Between the real-time capture thread
    and the tokio broadcast there is a plain `std::thread` at **default priority** whose only job
    is to change the channel type. (C-120)
27. **The logging rule's cost is not stated.** `tprintln!`/`teprintln!` also emit a Tauri IPC
    event with a full JSON serialization and take two foreign Tauri mutexes, **unconditionally,
    from real-time capture and audio threads**, 429 call sites. (C-183, C-184)
28. **The `DISPLAY_CORRELATION_LOCK` rationale understates it.** It is not only "serializes
    virtual-display creation across its `spawn_blocking`/settle awaits" — it is held
    **process-wide across a ≤5 s attach poll** and, on macOS, across up to 3 s of `activate_mode`
    polling, twice for a Retina client. (C-023, C-012)
29. **The "one PRD" claim.** `CLAUDE.md`'s stale-reference list does not mention that the only
    `PRD.md` actually in the tree is `linux-vdd/PRD.md` (a `vdutil` virtual-display document),
    which is what `linux.rs`'s "PRD §5.7" citation resolves to — and it has no §5.7 and nothing
    about input. The 22 `PRD §5.x` citations in `macos_utils/streamer/sck.rs` and the
    `M1/M2` markers in `gpu.rs`/`mod.rs` point at documents that never existed either; one of
    them (`mod.rs:37`) is a **user-visible error string**.
30. **The dev-box note is optimistic about what can be exercised.** `CLAUDE.md` says
    "`cargo check`/`clippy`/`test`" can be run locally. Bare `cargo test` has been **red since
    2026-06-30** (nine doctests in the vendored fork fail to compile), and on the Windows box
    the x264 tests pass in 0.44 s **without loading libx264 or encoding anything**. (C-194)
